# API contract notes

`openapi.json` enumerates all 64 implemented operations, authentication/role metadata, path/query/header inputs, mutation bodies, key response schemas and errors. JSON is served under `/api/v1` via the same origin. Topic/problem IDs resolve course scope on the server; redundant course IDs in illustrative PRD paths were simplified without relaxing authorization.

Mutations require exact configured `Origin`; authenticated mutations also require `X-CSRF-Token` from `/me`. Cookies are HttpOnly/SameSite=Lax, Secure in production, expire after 24 hours, and are revocable. Anonymous activation/reset links are single-use. Errors use `{code,message,fieldErrors?,requestId?}`; validators return 422, conflicts 409, infrastructure 503. Maximum JSON body is 2 MiB; source/input/output fields also enforce UTF-8 byte limits. Lists are bounded and private responses are no-store.

## Mutation envelopes

Account activation returns `{user}`; reset/change returns `{message}`; logout/removal returns 204. Admin invitation returns `{user,message}`, status updates `{user}`, course creation/archive `{course}`, assignment `{membership}`. Faculty draft creation/publishing returns `{revision}`, lesson changes `{topic}`, question changes `{question}`, problem changes `{problem}`, ordering `{message}`. Lesson acknowledgment returns progress directly. Quiz create/resume returns `{attemptId}`, answer saving `{version}`, final grading `{attemptId,score,progress}`. Draft saving returns `{version}`. Execution returns 202 `{submissionId,status,pollAfterMs:2000}`.

Answer keys/explanations are omitted until the attempt is completed. Hidden execution cases are exactly `{position,hidden:true,verdict}`. They never include input, expected output, stdout, diagnostics, time, memory or Judge0 tokens. Public cases include permitted output/diagnostics/time/memory. Infrastructure failures remain separate from wrong answers.

Create/resume and grade serialize by student/topic. Draft version conflicts require explicit resolution. Execution UUID idempotency keys bind the complete request and cannot be reused for changed content. Published content/reparent operations are guarded in PostgreSQL. Archived courses reject writes while retained records remain readable to currently authorized users.

Prisma relation fields may extend non-secret curriculum/course/report objects. Application clients should use the documented fields rather than depend on undocumented extensions. Production OpenAPI should further tighten report schemas as client contracts stabilize; that does not authorize expanding exposed sensitive fields.

## Public student registration

`POST /auth/signup` accepts only `{name,email}` (trimmed name, 2–100 characters; valid normalized email, maximum 254 characters). It requires the configured Origin and has no session/CSRF requirement. It creates only a pending STUDENT with no password or enrollment. All valid new/existing addresses receive the same 202 `{message,delivery}` response, where delivery is `local-preview` or `email` according to server mail configuration. Pending students receive a fresh 24-hour single-use activation link; active/deactivated/staff accounts are untouched. Delivery failures are redacted; retry signup to resend. `/auth/activate` verifies the link and sets the password before login. Expired links return `TOKEN_EXPIRED` without activating the account. Public signup/activation/recovery share a 20-request/IP/15-minute limiter (200 in isolated tests). The unauthenticated local preview endpoint is enabled only for loopback development/test processes and returns action links without filesystem paths.

## Syllabus topic and review extensions

Topic identity is an arbitrary stable lowercase key (maximum 120 characters), independent of optional `visualizerKey`. `requiredActivities` contains LESSON plus any QUIZ/CODING/PRACTICAL requirements. `blockedActivities` records activity/reason pairs; blocked requirements cannot earn completion. `sourceTopicIds` must belong to the assigned source subject/unit; unit page mappings are checked. `authoringStatus` distinguishes COMPLETE_DRAFT, INCOMPLETE and SOURCE_BLOCKED. Incomplete authoring cannot publish even if a review flag is set. Supplemental modules do not certify complete coverage of their source paragraph group.

Draft topics, questions and problems expose `version`, `reviewerId` and `reviewedAt`. Material edits invalidate review in PostgreSQL; provided stale versions return SAVE_CONFLICT. POST `/faculty/:kind/:id/review` accepts `{version,approved}` for topics/questions/problems and records the authenticated review and audit event. It does not publish. Published content is immutable.

GET `/faculty/coverage?page=1&q=&subjectCode=` returns up to 50 source coverage rows, actual assigned-course draft mappings, totals and the registered simulation inventory. Administrators see all sources; faculty see only subjects in their assigned courses. GET `/faculty/courses/:id/draft-library?page=1` exposes up to 50 original library drafts from explicitly linked subjects. POST `/faculty/revisions/:id/import-drafts` accepts at most 100 keys; repeat imports skip existing keys and create no approval, publication or learner activity.

GET `/faculty/revisions/:id/validation` reports publication errors and per-topic review/activity coverage without publishing. Draft revision listings return at most ten recent revisions with 100 topics per page and `_count.topics`. Student `/courses/:id/topics?page=1` returns 100 topics plus page/pageSize/total. POST `/faculty/topics/:id/move` with `{direction:UP|DOWN}` reorders across pages. Full topic-order PUT remains supported with a 2000-topic bound.

Theory-only quiz mastery is NOT_APPLICABLE. Faculty insufficient-evidence counts exclude these topics; analytics report required/blocked activities and actual execution-provider failure counts separately. A missing secure executor blocks coding execution and completion while permitting saved drafts. No external practical evidence is fabricated.
