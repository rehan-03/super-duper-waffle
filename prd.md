# AlgoLearn product requirements

Version 2, 2026-10-13. This revision replaces the six-algorithm launch scope with the supplied four-year computing syllabus. React, Express, PostgreSQL, Prisma and the isolated execution worker remain the architecture. Existing users, memberships, published revisions and evidence must survive upgrades.

## Scope and users

Students register publicly, activate email, and access administrator-assigned courses. Faculty author and review learning material in assigned courses. Administrators select official subjects and elective alternatives explicitly, assign faculty, enroll students, manage account status, archive offerings and inspect audit/health records. Development semester provisioning is separate from institutional enrollment.

All four supplied PDFs remain authoritative references, including non-computing subjects. Computing coverage includes programming, algorithms, software engineering, databases, OS, networks, hardware, security, AI/ML, graphics, web/mobile and associated labs. Source paragraphs are split only at explicit topic/activity boundaries. Source text, authored explanations and unresolved extraction/source ambiguities are distinct. Scheme-only entries must not acquire invented syllabi.

## Learning and publication contracts

Learning topics have a stable key, title, optional visualizer, required activities, source mappings and explicit blocked activity reasons. A simulation is optional exploration and never creates mastery. External practical work cannot be represented as accepted coding. Provider failure is infrastructure status, not an incorrect solution. An unavailable secure provider prevents coding completion; it need not prevent publishing reviewed specifications for later practice.

Content is versioned under immutable published course revisions. Draft copying clears reviews. Review is a human faculty/admin assertion; automated import/validation never supplies it. Lessons and every assessment offered to students require review. Quiz publication checks 6/7/7 questions when quiz is required; coding checks two complete reviewed problems when coding is required. A blocked external practical may be described in a published lesson, but remains incomplete until a supported evidence workflow exists.

Quiz mix remains 6/4/0 unassessed or weak, 3/4/3 developing, 2/4/4 mastered. Scores below 60 are weak, 60-79 developing, 80+ mastered estimates. Unanswered items score incorrect but do not count toward the ten answered-family evidence floor. Quizzes contain ten distinct questions; retries favor unused families. Code drafts use optimistic versions per learner/course/problem/language; accepted coding requires every sample/hidden case. Comparison normalizes line endings and trailing whitespace only.

## Pages, APIs and data

Public: login, signup, activation, reset. Student: dashboard, courses, official curriculum, lesson/activity tabs, standalone visualizer library, quiz/results/history, coding workspace and progress. Faculty: course content studio with coverage, validation, preview and review, course/student analytics. Admin: overview, accounts, courses, subject selection, memberships, audit and service health. Profile supports password changes.

REST remains /api/v1, same-origin cookie sessions plus CSRF. Existing endpoints/error envelope remain compatible; additions expose activity requirements, visualizer links, source-topic mappings, review metadata, coverage and blocked reasons. See docs/api_contract.md and docs/openapi.json. Database records remain relational with additive migrations; source text and educational content are separate. Browser/API never execute learner code. A separate durable-job worker talks to the configured private execution provider.

## Release evidence and external gates

docs/requirements_traceability.md tracks implementation separately from verification. docs/curriculum_source_audit.md tracks source ambiguities. Content coverage distinguishes complete drafts, incomplete authoring, unsupported infrastructure and missing source material. Never relabel incomplete authoring as an external blocker. Faculty approval, SMTP delivery, real isolated execution and institutional deployment remain external gates when unavailable. No generated scores, fabricated reviews or simulated production execution are acceptable.
